# CSGP 학습 커리큘럼 — 콘솔 게임 7종으로 배우는 개발 기술

> **CSGP (Console Game Pack)** 는 단순한 게임 모음이 아니라, **C/C++ 콘솔 게임을 하나씩 만들어 가며 개발 기술을 단계적으로 습득**하도록 구성한 학습 커리큘럼의 결과물이다.
> 게임 하나가 하나의 "학습 단계"이며, **이전 단계에서 익힌 기술 위에 새로운 기술을 한 겹씩 쌓는다.** 이 문서는 그 배움의 지도(map)다.
>
> 함께 볼 문서: [`README.md`](../README.md) · [`handover.md`](../handover.md) · [`CLAUDE.md`](../CLAUDE.md) · 게임별 설계는 [`Docs/`](.)의 각 GDD.

최종 갱신 기준일: 2026-07-10

---

## 0. 이 커리큘럼의 설계 철학

- **작게 시작해서 쌓아 올린다.** 자료구조 하나로 굴러가는 스네이크에서 출발해, 마지막엔 절차적 맵 위에서 풀링된 대량 오브젝트가 싸우는 종합 게임(배틀 시티)까지 만든다.
- **하나의 게임 = 하나의 새 기술 묶음.** 매 단계는 반드시 *이전에 안 배운* 기술을 최소 하나 이상 새로 도입한다. 그래서 순서가 곧 난이도다.
- **엔진과 콘텐츠를 분리한다.** 게임 로직을 짜기 전에, 모든 게임이 공유하는 토대(게임 루프·렌더링·입력·타이머·씬)를 먼저 이해한다. 이것이 **0단계(엔진)** 다.
- **콘솔이라는 제약을 정면으로 배운다.** 더블 버퍼링, 전각 문자 2칸, 타이머 해상도(10~16ms), CP949 인코딩 같은 콘솔 특유의 문제를 회피하지 않고 정공법으로 다룬다.

> 커리큘럼의 큰 흐름: **자료구조 → 알고리즘 → 물리/스크롤 → 시스템 → 메모리·성능 → 알고리즘 심화 → 종합.**
>
> ℹ️ **순서 개정(강의용, B안)**: 5·6단계를 **Galaga(풀링) → Maze(알고리즘 심화)** 로 배치한다. 이유 셋 — ① Road Fighter의 "매 프레임 벡터 재생성" 바로 다음에 Galaga 풀을 두어 **풀링 대조 학습이 인접**, ② 난이도가 Galaga(중)→Maze(중상)→Battle City(상)로 **단조 증가**, ③ Maze의 **맵 생성 + BFS를 캡스톤(Battle City) 직전에 배워 바로 재사용**. (이전 A안은 Maze→Galaga 순이었음.)

## 1. 학습 지도 (게임 7종 한눈에)

| # | 게임 | 이 단계에서 **처음 배우는** 핵심 기술 | 누적되는 역량 | 상태 |
|:---:|---|---|---|:---:|
| **1** | **Snake** | 동적 자료구조(`vector`+포인터), 충돌, 방향 입력, 상태머신 | 플레이어가 조작하는 게임 | ✅ 구현 |
| **2** | **Tetris** | 2D 그리드 보드, 회전/월킥 알고리즘, 라인 클리어, 7-bag 랜덤, DAS | 규칙과 알고리즘이 있는 게임 | ✅ 구현 |
| **3** | **Dino** | 물리(중력/점프), 월드 스크롤, 절차적 스폰, AABB, 스프라이트 애니메이션 | 살아 움직이는 세계 | ✅ 구현 |
| **4** | **Road Fighter** | 엔티티 시스템(이종 오브젝트), 리소스 관리, 무적 상태, 시간 기반 스테이지, HUD | 시스템이 얽힌 게임 | ✅ 구현 |
| **5** | **Galaga** | 오브젝트 풀링(`Pool<T,N>`·active 플래그·재사용), 대량 오브젝트 | 성능·메모리를 의식하는 코드 | ✅ 구현 |
| **6** | **Maze** | 맵 생성 알고리즘 5종 + 경로탐색 4종, union-find, 분할정복, 격자 좌표계 | 알고리즘을 주제로 다루기 | ✅ 구현 |

## 2. 0단계 — 엔진 기반 (프레임워크)

게임을 만들기 **전에** 갖춰야 할 공통 토대. 모든 게임이 이 위에서 돈다. (`FrameWork/`, `framework.h`, `main.cpp`)

| 개념 | 구현 위치 | 무엇을 익히나 |
|---|---|---|
| **게임 루프** | `main.cpp` | `입력 → Update → Render → Flip → 프레임 대기`의 고정 루프. 모든 실시간 게임의 심장. |
| **싱글턴 패턴(템플릿)** | `singleton.h` | `template<typename T>`로 매니저 하나만 존재하게. C++ 템플릿·정적 멤버 입문. |
| **더블 버퍼링** | `ScreenManager` | 콘솔 화면 버퍼 2개(`hBuffer[2]`)를 번갈아 그려 깜빡임 제거. |
| **전각 문자 좌표계** | `ScreenManager::OnDraw` | 전각 1글자 = 콘솔 2칸 → **출력 시 `x*2`**. 논리/화면 좌표 분리. |
| **폴링 입력 + 엣지/레벨** | `InputManager` | `GetAsyncKeyState` + `bitset`. `OnKeyDown`(엣지) vs `OnKeyStay`(레벨). |
| **틱 타이머 / 프레임 제한** | `TimerManager` | `GetTickTimer(sec)` "N초마다 true", `SetFrame(ms)` 프레임률 고정. |
| **씬 시스템 + 소유권** | `SceneManager` | `map<int, IContent*>` 씬 등록·전환, 매니저가 씬 소유·해제. |
| **인터페이스 / 상태머신** | `IContent`, `IGameContent` | 순수가상 + 가상 소멸자, `_EPhase{ TITLE, INGAME }` 페이즈. 1단계부터 모든 게임이 재사용. |

> **워밍업 — `Load`(로딩 연출)**: 입력도 상태도 없이 "시간이 흐르면 화면이 바뀐다"만 다루는 가장 단순한 씬. 2D 배열(`curtain`)과 타이머 애니메이션으로 렌더링 감각을 먼저 잡는다. (씬은 있으나 게임이 아니라 7종에서 제외.)

### 왜 먼저인가
1단계 이후 모든 게임은 "이 껍데기(`IGameContent`)를 상속해 빈칸(`OnInGameUpdate/Render`)만 채우는" 방식이다. 엔진을 이해하면 이후 단계는 **오직 그 게임 고유의 로직에만 집중**할 수 있다.

## 3. 1단계 — Snake: 자료구조와 충돌

**결과물:** 몸이 자라는 뱀. 아이템 획득·트랩/벽/자기 몸 충돌·터널 워프·타이틀 메뉴. (`SnakeContent.*`, [GDD](SnakeContent_GDD.md))

### 처음 배우는 기술
- **동적 자료구조 + 포인터 관리.** `std::vector<Snake*>`로 몸통을 관리하고 `new/delete`로 마디를 늘린다. **힙 메모리와 소유권**을 처음 직접 다룬다.
- **컨테이너 순회(iterator).** 몸/아이템/트랩 리스트를 훑는다.
- **충돌 판정.** 머리 vs (벽 / 자기 몸 / 아이템 / 트랩)의 좌표 비교 — 게임 규칙의 핵심.
- **방향 입력과 무효 입력 차단.** `_EDIRECT` + `lastDirect`로 역주행 금지. "입력을 그대로 믿지 않는다".
- **상태머신 실전.** 0단계의 `_EPhase`로 타이틀↔인게임 전환, 게임 고유 서브 상태(`_ESELECT`)를 얹는다.

### 왜 이 순서인가
**플레이어의 입력이 자료구조를 바꾸고 → 충돌이 규칙을 만드는** 상호작용의 최소 완성형. 살아있는 게임의 첫 형태다.

---

## 4. 2단계 — Tetris: 알고리즘과 그리드

**결과물:** 표준 10×20 테트리스. 7-bag·SRS 회전+월킥·홀드·고스트·하드드롭·라인클리어·레벨. (`TetrisContent.*`, [GDD](TetrisContent_GDD.md))

### 처음 배우는 기술
- **고정 2D 그리드 보드.** `int board[H][W]` — 배열이 게임의 메인 자료구조로 승격.
- **좌표 변환·회전 알고리즘.** 회전 상태 + **월킥** + 충돌검사로 SRS 회전.
- **랜덤 생성기 설계.** 7-bag Fisher-Yates 셔플로 "무작위를 공정하게".
- **알고리즘: 라인 클리어.** 가득 찬 행 탐지·제거·낙하 — 배열 조작의 정석.
- **입력 타이밍 제어(DAS).** 타이머를 입력에 응용(꾹 누르면 일정 간격 반복).

### 왜 이 순서인가
Snake가 "직관적 충돌"이었다면 Tetris는 **명시적 규칙과 알고리즘**의 게임. **자료구조 위에서 돌아가는 알고리즘**을 본격 설계한다.

---

## 5. 3단계 — Dino: 물리와 스크롤

**결과물:** 크롬 디노 러너. 점프(중력)/숙이기/빠른착지, 선인장·익룡, 가속, 밤낮. (`DinoContent.*`, [GDD](DinoContent_GDD.md))

### 처음 배우는 기술
- **물리 시뮬레이션.** `float`로 속도/가속/중력 → 부드러운 점프. 정수 격자를 넘어 **연속 운동**.
- **월드 스크롤(카메라 감각).** 플레이어 고정, **세계가 흐른다**.
- **절차적 생성.** 거리 간격 기준으로 장애물 무한 생성.
- **AABB 충돌.** 점 충돌에서 **면 충돌**로 발전.
- **스프라이트·프레임 애니메이션.** 여러 줄 스프라이트 + 프레임 토글.

### 왜 이 순서인가
Tetris가 "정지된 보드 위 규칙"이라면 Dino는 **시간과 물리로 스스로 흐르는 세계**. 러너/슈터/플랫포머로 확장되는 핵심 감각이다.

---

## 6. 4단계 — Road Fighter: 엔티티 시스템과 리소스

**결과물:** 5차선 레이서. 적(일반/고속위빙/트럭)·아이템(연료◆/보너스★)·장애물▲, 연료·목숨·무적, 시간 기반 스테이지. (`RoadFighterContent.*`, [GDD](RoadFighterContent_GDD.md))

### 처음 배우는 기술
- **엔티티 시스템(이종 집합).** 하나의 `struct Entity{ type; … }`로 적·트럭·아이템·장애물을 **한 리스트에서** 관리하고 `type`에 따라 분기.
- **리소스 관리.** 연료·목숨이라는 소모/회복 자원, 자원 0의 실패 조건.
- **일시적 상태.** 무적 프레임(`invTimer`) — 상태에 수명을 준다.
- **충돌의 분기 처리.** 같은 충돌이라도 아이템은 획득, 차량은 피해.
- **시간 기반 스테이지 + HUD.**

### 왜 이 순서인가
앞선 단계의 기술을 **한 게임 안에서 동시에** 쓰며, 여러 시스템(엔티티·자원·스테이지·UI)이 물려 도는 **시스템 설계**를 경험한다.

---

## 7. 5단계 — Galaga: 오브젝트 풀링 (엔지니어링 성숙)

**결과물:** 편대 슈팅. 총알·적·폭발을 풀로 관리. (✅ `GalagaContent.*`, [GDD](GalagaContent_GDD.md))

### 처음 배우는 기술
- **오브젝트 풀(`Pool<T, N>`).** 고정 크기 배열을 미리 잡고 `active` 플래그로 켜고 끄며 슬롯을 **재사용**. **게임 루프 안에서 `new/delete`·재할당 0회**.
- **대량 오브젝트 관리.** 초당 수십 개 생겼다 사라지는 총알을 상한 고정 비용으로.
- **"측정 후 최적화".** 선형 탐색 스폰 → 프리 리스트 O(1)로 개선.

### 왜 이 순서인가
바로 앞 단계까지 오브젝트를 **순진하게** 다뤘다 — Snake는 `new/delete`, Dino·Road Fighter는 매 프레임 벡터 재생성. **Road Fighter 직후** 슈팅으로 넘어오며 그 방식의 한계를 정면으로 드러내고, **풀링으로 고치는 대조 학습**이 된다. "동작하는 코드 → 성능·메모리를 의식하는 코드"로 올라서는 단계. (강의 편성상 Road Fighter 바로 다음에 두어 대조를 극대화한다.)

---

## 8. 6단계 — Maze: 알고리즘 심화 (생성 + 탐색)

**결과물:** 스테이지마다 다른 알고리즘으로 생성된 미로. 경로탐색 시각화·최단 걸음 별점. (`MazeContent.*`, [GDD](MazeContent_GDD.md))

### 처음 배우는 기술
- **맵 생성 알고리즘 5종(스테이지 축).** Binary Tree(편향) → Recursive Backtracker(스택·백트래킹) → Randomized Prim(프론티어) → Kruskal(**union-find**·MST) → Recursive Division(**분할정복**). 알고리즘마다 미로의 성격이 달라진다.
- **경로탐색 4종(공통 메커닉).** BFS / DFS / A*(휴리스틱) / 벽 따라가기 — 탐색 과정을 색으로 시각화해 비교 학습.
- **분리집합·분할정복·격자 좌표계**, 최단경로 기반 채점.

### 왜 이 순서인가
Tetris에서 "자료구조 위의 알고리즘"을 맛봤다면, Maze는 **알고리즘을 주제 그 자체로** 끌어올린 심화 단계. 여기서 익힌 **절차적 생성 + 경로탐색(BFS)** 을 **바로 다음 캡스톤(Battle City)에서 그대로 재사용**하므로, 종합 과제 직전에 배치해 "배우고 즉시 응용"이 되게 한다.

---

## 9. 7단계 — Battle City: 종합 캡스톤 (맵 생성 + 풀링)

**결과물:** 탱크 액션. 절차적 전장 위에서 기지를 방어하며 적을 전멸. (✅ `BattleCityContent.*`, [GDD](BattleCityContent_GDD.md))

### 처음 배우는 기술 / 종합
- **맵 생성 + 오브젝트 풀링의 결합.** Maze의 **절차적 생성 + 연결성 검증(flood fill)** 으로 전장을 만들고, Galaga의 **풀**로 총알·적 탱크·폭발·아이템을 돌린다.
- **파괴 가능 지형과 타일 상호작용**(벽돌/철벽/물/숲/얼음/기지), 기지 방어라는 승패 축.
- **적 AI**(기지 추적/플레이어 추적) — Maze의 **BFS 경로탐색을 재사용**할 수 있다.

### 왜 이 순서인가
앞선 두 기술 축(**5단계 풀링 · 6단계 생성**)이 **한 게임에서 수렴**한다. 절차적 맵·대량 오브젝트·AI·타일 규칙이 동시에 얽히는 커리큘럼의 졸업 과제.

## 10. 기술 습득 총정리 (기술 → 최초 도입 / 심화)

| 기술 영역 | 최초 도입 | 이후 심화 |

## 11. 이 커리큘럼을 따라가는 법

1. **0단계(엔진) 먼저 읽기** — `main.cpp` 게임 루프 → `framework.h` → 매니저 4종 → `IContent`/`IGameContent`.
2. **게임은 위 순서(Snake→…→Battle City)대로** 코드를 읽고, 각 게임의 `On*Update/On*Render`를 진입점으로 삼는다.
3. 게임별 상세 설계는 [`Docs/`](.)의 GDD 참고(Snake(as-built)/Tetris/Dino/RoadFighter/Galaga/Maze/BattleCity). 커리큘럼 이후 게임 백업은 [`FUTURE_GAMES.md`](FUTURE_GAMES.md).
4. **새 게임을 직접 붙여 보는 것**이 다음 실습 — 절차는 [`handover.md`](../handover.md) §7 또는 [`CLAUDE.md`](../CLAUDE.md) "새 씬 추가 절차".
