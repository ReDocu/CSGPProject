# GameDevTycoon — Game Design Document (콘솔 게임회사 운영하기)

> **1부 C 기본 문법 커리큘럼**([`study_index.md`](../study_index.md))의 실습 게임. 플레이어는 1인 게임 회사의 사장이 되어 직원을 고용하고 게임을 만들어 팔며 회사를 키운다.
> **표준 C만 사용**하는 텍스트 기반 **턴제(월 단위)** 경영 시뮬레이션 — 2부의 CSGP 프레임워크(Win32 콘솔 API·실시간 루프·C++)를 **쓰지 않는다**. `printf`/`scanf`만으로 완성되도록 설계했다.
> 함께 볼 문서: [`study_index.md`](../study_index.md)(장별 문법 목차) · [`CURRICULUM.md`](CURRICULUM.md)(2부) · [`CLAUDE.md`](../CLAUDE.md)(인코딩 규칙).
> **v1.0 구현 완료** — 코드: [`Study/Tycoon/`](../Study/Tycoon/) (표준 C, 7모듈 + `build.bat`). 장별 학습 순서는 §11 마일스톤(= 1부 15개 장) 참고.

## 0. 이 게임의 설계 의도 (커리큘럼: **1부 — C 기본 문법**)

이 게임의 배움 주제는 게임 기술이 아니라 **C 문법 그 자체**다. 그래서 설계 원칙이 2부 게임들과 반대다:

- **실시간이 아니라 턴제.** 게임 루프·타이머·더블 버퍼링이 필요 없다. `while` 한 바퀴 = 1개월. 5장(반복문)을 배우는 순간 게임이 "돌기" 시작한다.
- **모든 시스템이 문법 단원 하나와 1:1 대응.** 직원 목록=배열(7장), 직원/프로젝트 정의=구조체(9장), 무제한 고용=동적 할당(11장), 세이브=파일 입출력(13장). 기능을 추가하고 싶으면 다음 문법을 배워야만 하도록 의존성을 배치했다.
- **숫자가 곧 게임.** 경영 시뮬은 상태(자본금·명성·능력치)와 계산(정산·평점·판매)이 전부라, 그래픽 없이 `printf` 표만으로 완성된 재미가 나온다.
- **완성이 빠르고, 끝까지 자란다.** v0.3(5~6장)에 이미 파산 엔딩이 있는 최소 게임이 되고, v1.0(15장)까지 같은 코드가 계속 자란다 — "내 코드가 크는" 경험.

> 대조: 2부 0단계 엔진은 "매 프레임 다시 그리는 실시간 세계"를 배운다. 1부는 그 전에 **값·분기·반복·데이터 모양**이라는 프로그래밍의 뼈대를 익히는 단계다.

## 2. 핵심 게임 루프 (턴제 — 1턴 = 1개월)

```
[월 시작: 메인 메뉴] ─ 행동 선택 (횟수 제한 없음, 시간 안 흐름)
   ├─ 게임 개발    : 새 프로젝트 기획(제목·장르·규모·기획비) / 진행 상황 확인 / 출시 결정
   ├─ 직원 관리    : 지원자 확인·고용 / 해고 / 명단 보기
   ├─ 회사 현황    : 자본금·명성·출시작·월 고정비 요약
   └─ 저장 / 종료
[다음 달 진행] 선택 시 ──▶ 한 달 경과 처리(순서 고정):
   ① 개발 진행     프로젝트 progress/quality/fun 누적 (직원+사장 능력치 합산)
   ② 출시 처리     progress ≥ 필요치인 프로젝트 → 평점 산정 → 판매 목록 등록
   ③ 판매 정산     판매 중인 게임들의 이번 달 판매량·수익 계산 (매달 감쇠)
   ④ 랜덤 이벤트   확률로 1건 발생 (호황·버그 사태·월급 인상 요구·지원금…)
   ⑤ 지출          직원 월급 합계 + 사무실 임대료
   ⑥ 월 리포트     수입/지출/순이익 표 출력, 자본금 갱신
   ⑦ 판정          자본금 < 0 → 파산 엔딩 / 승리 조건 → 축하 엔딩(계속하기 가능)
   ⑧ 달력 진행     month++, 12월 지나면 year++
```

입력을 기다리는 동안 아무 일도 일어나지 않는다(블로킹 입력 = `scanf`). 실시간성이 없으므로 **프레임·타이머 개념이 등장하지 않는다.**

## 3. 화면 구성 (텍스트 화면 목록)

논리 해상도 없음 — 화면은 `printf` 출력 흐름이다. 테두리는 **ASCII 문자만**(`= - | +`) 사용해 인코딩·정렬 문제를 차단한다(§12). 화면 전환 시 `system("cls")` 후 다시 출력.

### 3.1 메인 메뉴 (매월 허브)

```
==================================================
  EQMENT STUDIO          2026년  3월    명성 ★ 12
  자본금 4,350만원        직원 3명    개발중 1건
==================================================
  [1] 게임 개발        [2] 직원 관리
  [3] 회사 현황        [4] 출시작 목록
  [5] 저장하기         [6] 다음 달 진행 >>
  [0] 게임 종료
--------------------------------------------------
  >> 선택:
```

### 3.2 개발 중 프로젝트 상태

```
--------------------------------------------------
  개발중 : "던전 앤 라면"  (RPG / 중형)
  진행도 [##########----------]  50 / 100
  품질 34   재미 28          개발 4개월차
--------------------------------------------------
  [1] 계속 개발   [2] 조기 출시   [0] 뒤로
```

### 3.3 월 리포트 (다음 달 진행 시)

```
============ 2026년 3월 결산 ============
  판매 수익     "던전 앤 라면"      +  820만원
  이벤트        정부 지원금 선정    +  500만원
  직원 월급     3명                 -  650만원
  사무실 임대료                     -  100만원
  ----------------------------------------
  순이익                            +  570만원
  자본금  4,350만원 -> 4,920만원
==========================================
  (Enter를 누르면 계속)
```

### 3.4 기타 화면
| 화면 | 내용 |
|------|------|
| 타이틀 | 로고(ASCII 아트) → 회사명 입력(8장) → 새 게임/불러오기(13장) |
| 기획 | 제목 입력 → 장르 5종 선택 → 규모 3종 선택 → 기획비 확인/지불 |
| 직원 관리 | 명단(이름·능력치·월급·근속) / 이번 달 지원자 1~2명 고용 / 해고 |
| 출시 결과 | 평점 발표 연출(별점) + 첫 달 판매량 |
| 출시작 목록 | 역대 게임: 제목·장르·평점·누적 판매 |
| 엔딩 | 파산 / 자산 1억 / 명작(평점 9.0+) — 최종 통계 출력 |

## 4. 입력 방식

| 입력 | 방식 | 배우는 장 |
|------|------|:---:|
| 메뉴 선택 (정수) | `scanf("%d", &sel)` + 범위 검증(잘못된 값 재입력) | 2·4장 |
| 회사명·게임 제목 (문자열) | `fgets` + 개행 제거 (`scanf %s`의 공백 문제를 8장에서 학습 소재로) | 8장 |
| 계속 진행 (Enter 대기) | `getchar()` 버퍼 비우기 | 2장 |

> **입력 버퍼 문제를 일부러 겪게 한다**: `scanf("%d")` 뒤에 남는 `\n` 때문에 `fgets`가 빈 줄을 읽는 현상은 C 입문의 고전 함정 — 8장에서 정면으로 다루고 `while(getchar()!='\n');` 패턴으로 해결한다.

## 5. 게임 시스템

### 5.1 회사 (자원)
| 자원 | 초기값 | 설명 |
|------|-----:|------|
| 자본금 `money` | 5,000 (만원) | 모든 지출/수입의 대상. **음수가 되는 순간 파산** |
| 명성 `fame` | 0 | 출시작 평점에 따라 증감. 판매량 보정 `(100+fame)/100` |
| 날짜 `year/month` | 2026년 1월 | 월 단위 진행 |

단위는 **만원(int)** — 큰 수의 자릿수 문제 없이 정수 연산만으로 경제가 돈다(1장 자료형 학습과 연결). 평점(`float`)만 실수를 쓴다.

### 5.2 사장 (플레이어)
- 사장도 개발자다: 고정 능력치 **개발력 3 / 창의력 3** — 직원이 없어도(1~6장 시절) 개발이 진행되도록 보장.
- 사장 월급은 없다(회사 = 나).

### 5.3 직원
| 속성 | 범위 | 설명 |
|------|------|------|
| 이름 `name` | 문자열 | 지원자 풀에서 랜덤 |
| 개발력 `dev` | 1~10 | 진행도·품질에 기여 |
| 창의력 `cre` | 1~10 | 재미에 기여 |
| 월급 `salary` | (dev+cre)×30 만원 | 능력에 비례 — 좋은 직원 = 비싼 고정비 |
| 근속 `months` | 0~ | 이벤트(월급 인상 요구) 트리거 조건 |

- **7장(배열)**: 고정 4슬롯 — 5번째 고용 시 "사무실이 좁습니다" 거절 → **11장(동적 할당)**에서 제한 해제(`realloc` 확장). *배열의 한계를 몸으로 느끼고 malloc으로 푸는 서사.*
- 매월 지원자 1~2명이 랜덤 능력치로 등장, 고용/무시 선택. 해고는 즉시(퇴직금 = 월급 1개월분).

### 5.4 게임 프로젝트 & 개발 사이클
동시 진행 1건(MVP). 사이클: **기획 → 개발(매월 자동 진행) → 출시 → 판매**.

| 규모 | 기획비 | 필요 진행도 | 장당 이익 |
|------|-----:|-----:|-----:|
| 소형 | 200만원 | 100 | 판매량÷2 만원 |
| 중형 | 500만원 | 200 | 판매량÷2 ×2 |
| 대형 | 1,200만원 | 400 | 판매량÷2 ×3 |

- **장르 5종**: RPG / 액션 / 퍼즐 / 시뮬레이션 / 스포츠 (`enum Genre`). 매 분기 **유행 장르**가 랜덤 선정 — 일치 시 판매 1.5배.
- 매월 개발 진행(사장+직원 전원):
  - `progress += 15 + Σdev`
  - `quality += Σdev`, `fun += Σcre + rand()%3`
- `progress ≥ 필요치` → 다음 달 진행 시 자동 출시. **조기 출시** 가능(§3.2) — 진행도가 모자란 만큼 평점 페널티(전략 요소).

### 5.5 출시 & 평점
```
base   = (quality + fun) * 100 / 필요진행도     // 0~100 스케일
rating = base / 10.0                            // 0.0 ~ 10.0
       + (유행 장르 일치 ? +0.5 : 0)
       + 랜덤(-0.5 ~ +1.0)                      // 12장 전까지는 랜덤 항 없음
       (조기 출시 시 base를 progress/필요치 비율로 감산)
rating = clamp(rating, 0.0, 10.0)
```
- 평점에 따라 명성 증감: 8.0+ → `fame += 10` / 6.0+ → `+5` / 4.0 미만 → `-5`.
- **평점 9.0 이상 = 명작** → 승리 엔딩 조건 충족.

### 5.6 판매 & 수익 (출시 후 매월)
```
첫 달 판매량 = rating × rating × 100 × 규모계수(1/2/4)
             × (100 + fame) / 100
             × (유행 일치 ? 1.5 : 1.0)          // 장 단위(정수)
다음 달부터  = 전월 × 50%  (판매량 < 100장이면 판매 종료, 최대 6개월)
월 수익(만원) = 판매량 ÷ 2 × 규모 이익계수(1/2/3)
```
예: 평점 7.0 소형, 명성 0 → 첫 달 4,900장 = 2,450만원 → 이후 1,225 → … 총 ≈ 4,800만원. *(수치는 §10 밸런스 초안 — 튜닝 대상)*

### 5.7 랜덤 이벤트 (12장에서 도입)
매월 ④단계에서 30% 확률로 1건. `rand()%100` + `switch` 실습.

| 이벤트 | 효과 | 확률 비중 |
|--------|------|:---:|
| 정부 지원금 | `+500만원` | 15 |
| 게임쇼 호황 | 이번 달 판매량 ×2 | 15 |
| 버그 사태 | 개발중 프로젝트 `quality -20` | 20 |
| 월급 인상 요구 | 근속 6개월+ 직원: 수락(+월급20%) / 거절(퇴사) | 20 |
| 악성 리뷰 | `fame -5` | 15 |
| 스카우트 제의 | 능력치 8+ 지원자 등장(월급 1.5배) | 15 |

- 유행 장르 변경은 이벤트가 아니라 **분기마다(3·6·9·12월) 항상** 재추첨.
- 12장 전 버전에는 이벤트가 없다 — 매달 결과가 완전히 예측 가능하다가, 12장에서 게임이 갑자기 "살아난다"(랜덤의 가치를 체감).

### 5.8 월 지출 (고정비)
| 항목 | 금액 |
|------|-----:|
| 사무실 임대료 | 100만원/월 |
| 직원 월급 | Σ salary |

수입이 없어도 매달 나가는 돈 — **아무것도 안 하면 파산**하는 시간 압박이 게임의 심장이다.

### 5.9 승리 / 패배
| 조건 | 판정 시점 | 결과 |
|------|-----------|------|
| 자본금 < 0 | 매월 ⑦ | **파산 엔딩** — 최종 통계(생존 개월·출시작·최고 평점) |
| 자산 10,000만원(1억) 도달 | 매월 ⑦ | **거상 엔딩** — 계속하기 선택 가능 |
| 평점 9.0+ 게임 출시 | 출시 시 | **명작 엔딩** — 계속하기 선택 가능 |

## 6. 상태 머신 (턴제 — 함수 호출 구조로 표현)

실시간 페이즈 머신(2부 `IGameContent`) 대신, **화면 = 함수** 인 단순한 호출 구조다(6장 함수 학습과 연결):

```
main()
 └─ TitleScreen()            타이틀 → 회사명 입력 → 새게임/로드
     └─ GameLoop()           while (!gameOver) — 5장에서 생기는 심장
         ├─ MainMenu()       switch (선택)
         │    ├─ DevMenu()      기획/확인/조기출시
         │    ├─ StaffMenu()    고용/해고/명단
         │    ├─ StatusScreen() 회사 현황
         │    ├─ ReleaseList()  출시작 목록
         │    └─ SaveGame()
         └─ AdvanceMonth()   ①~⑧ 한 달 처리 (§2)
              └─ CheckEnding()  파산/승리 → gameOver = 1
 └─ Ending()                 최종 통계
```

`gameOver` 플래그(그리고 15장의 `enum Ending { NONE, BANKRUPT, RICH, MASTERPIECE }`)가 상태의 전부다.

## 7. 데이터 설계 (C 구조체 — 9장에서 정의)

```c
typedef enum { G_RPG, G_ACTION, G_PUZZLE, G_SIM, G_SPORTS, GENRE_COUNT } Genre;
typedef enum { S_SMALL, S_MEDIUM, S_LARGE } Scale;

typedef struct {            /* 직원 — 9장 */
    char name[20];
    int  dev, cre;          /* 개발력 / 창의력 (1~10) */
    int  salary;            /* 만원/월 */
    int  months;            /* 근속 */
} Employee;

typedef struct {            /* 개발 중 프로젝트 — 9장 */
    char  title[30];
    Genre genre;
    Scale scale;
    int   progress, need;   /* 진행도 / 필요치 */
    int   quality, fun;
    int   devMonths;
    int   active;           /* 0 = 프로젝트 없음 */
} Project;

typedef struct {            /* 출시작 — 판매 중/종료 */
    char  title[30];
    Genre genre;
    Scale scale;
    float rating;
    int   monthSales;       /* 이번 달 판매량 (매월 감쇠) */
    int   totalSales;
    int   monthsOnSale;     /* 6 도달 or 판매<100 → 종료 */
} Release;

typedef struct {            /* 회사 (게임 전체 상태) */
    char      name[20];
    int       money, fame;
    int       year, month;
    Employee *staff;        /* 7장: Employee staff[4] → 11장: 동적 배열 */
    int       staffCount, staffCap;
    Project   proj;
    Release   shelf[50];    /* 출시작 목록 */
    int       shelfCount;
    Genre     trend;        /* 유행 장르 */
} Company;
```

- 1~8장은 구조체 없이 **낱개 전역 변수**(`money`, `fame`, `staffDev[4]`…)로 만든다. 9장에서 구조체로 **리팩터링**하는 것 자체가 실습 — "왜 구조체가 필요한가"를 겪은 뒤에 배운다.
- 10장부터 모든 시스템 함수는 `Company *c`를 받는다(전역 변수 제거) — 포인터의 필요성을 설계로 강제.

## 12. 인코딩 · 주의사항

- **소스 인코딩**: 한글 문자열 리터럴(`"자본금"` 등)을 쓰므로 `.c` 파일은 **CP949로 저장**(저장소 규칙과 동일 — [`CLAUDE.md`](../CLAUDE.md)). 한국어 Windows 콘솔 기본 코드페이지가 CP949라 `printf` 출력이 그대로 맞는다. *UTF-8 소스 + `chcp 65001` 조합은 쓰지 않는다(변수 하나 더 늘어남).*
- **화면 문자**: 테두리·게이지는 **ASCII만**(`= - | + # >`). 전각은 `★` 등 CP949 왕복 검증된 것만 최소 사용. 전각 폭 정렬 문제(2부 §좌표계)가 없도록 표 정렬은 `printf("%-10s %8d", …)` 서식으로 해결 — 서식 지정자 학습 소재.
- **MSVC `scanf` 경고**: C4996(`scanf` deprecated) → 파일 첫 줄 `#define _CRT_SECURE_NO_WARNINGS` 로 통일(표준 C 유지를 위해 `scanf_s` 대신). 이유를 2장에서 한 번 설명.
- **입력 버퍼**: `scanf("%d")` 후 남는 개행 → `fgets` 오동작. 8장의 핵심 학습 소재(§4).
- **`rand` 시드**: `srand((unsigned)time(NULL))` 은 `main` 에서 **한 번만**(12장 단골 실수).
- **동적 메모리**: `realloc` 반환값을 임시 포인터로 받기, 종료·로드 전 `free` — 11·13장에서 명시적으로 다룬다.
- **2부와의 경계**: 이 게임에 콘솔 API(`SetConsoleCursorPosition` 등)·C++ 문법을 **넣지 않는다**. "깜빡임 없는 화면"이 탐나기 시작하면 그것이 2부(더블 버퍼링)로 넘어갈 때가 됐다는 신호다.

## 13. 향후 확장 (Out of Scope for v1.0)

- **동시 다중 프로젝트** — `Project proj` → 동적 배열 (11장 복습).
